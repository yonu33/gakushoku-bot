# gakushoku-bot

会津大学 学生食堂の「日替わりランチ」と「夕食セット」を Discord に投稿する Bot です。Cloudflare Workers の Cron Triggers で動いています。

> [!NOTE]
> 個人の非公式プロジェクトです。会津大学および学生食堂の運営者（Student Life Support）とは関係ありません。
> メニューは変更されることがあります。正確な情報は[学生食堂の公式サイト](http://www.gakushoku.com/)で確認してください。

## 取得元サイトの運営者の方へ

この Bot は、User-Agent `gakushoku-bot/1.2 (+https://github.com/yonu33/gakushoku-bot)` で貴サイトの週替わりメニュー 2 ページにアクセスしています。アクセスは 1 日に最大 6 回です（詳しくは下の「取得元への配慮」）。

停止や方法の変更をご希望の場合は、[Issue](https://github.com/yonu33/gakushoku-bot/issues) でお知らせください。確認しだい停止します。

## 投稿内容

| 時刻 (JST) | 内容                           | 投稿しないとき                       |
| ---------- | ------------------------------ | ------------------------------------ |
| 10:00      | 当日の日替わりランチ           | 休み・掲載なし・取得失敗             |
| 15:30      | 当日の夕食セット               | 同上                                 |
| 19:00      | 翌日のランチと夕食セットの予告 | 取得失敗、平日なのにメニューが未掲載 |

予告で「明日はお休みです。」と投稿するのは、翌日が土日のときと、メニュー表で空欄や「お休み」になっているとき（祝日など）だけです。長期休み中などでサイトの更新が止まっている平日は、休みかどうか判断できないので投稿しません。

各投稿には出典として取得元ページの URL を付けています。

## 取得元への配慮（スクレイピングの方針）

| 項目           | 方針                                                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| アクセス先     | `univ_mn1.php` と `univ_mn2.php` の 2 ページのみ                                                                             |
| 頻度           | 1 日 3 回の定期実行で、各回最大 2 リクエスト（1 日最大 6 回）。同じ実行の中で同じページを取り直さない。リトライしない        |
| 名乗り         | User-Agent に Bot 名と連絡先（このリポジトリ）を入れる                                                                       |
| タイムアウト   | 10 秒で打ち切る                                                                                                              |
| robots.txt     | 2026-11-24 時点で存在しない（404）。利用規約などの掲示も見当たらない。掲示されたら従う                                       |
| 転載の範囲     | 日替わりランチと夕食セットのメニュー名のみ。出典 URL を付け、非営利で特定の Discord サーバー内でのみ共有する                 |
| データの保存   | 取得したページは保存しない。テストにも実際のページの HTML は含めず、構造だけを真似た架空のデータを使う                       |
| 停止する条件   | 運営者または大学から要請があったとき。403 や 429 などアクセスを拒否する応答が返るようになったとき                           |

## 安全対策

- **取得したテキストは外部入力として扱う。** 取得元が改ざんされても Discord に危険な内容が流れないよう、リンクを除去し、Markdown とメンションを無効化して、200 文字で切り詰めます（`src/discord.js`）。
- **取得に失敗したときは「お休み」と告知しない。** 失敗はログに残し、`ALERT_WEBHOOK_URL` が設定されていればそちらに通知します。
- **シークレットはリポジトリに置かない。** Webhook URL などは `wrangler secret` で管理します。ローカル用の `.dev.vars` は `.gitignore` に入っています。
- **動作確認エンドポイントは既定で投稿しない。** キーが漏れても、`post=1` を付けない限り Discord には何も流れません。

## セットアップ

```sh
npm install
npx wrangler secret put DISCORD_WEBHOOK_URL   # 投稿先
npx wrangler secret put TEST_SECRET_KEY       # 動作確認用のキー（未設定なら動作確認エンドポイントは無効）
npx wrangler secret put ALERT_WEBHOOK_URL     # 任意: 取得エラーの通知先（運用者だけが見るチャンネル）
npm run deploy
```

## 動作確認

### デプロイ済みの Worker

ブラウザで開きます（`キー` は `TEST_SECRET_KEY` に登録した値）。

```
https://gakushoku-bot.<サブドメイン>.workers.dev/?test=preview&date=2026-11-24&key=キー
```

URL に入れたキーはブラウザの履歴と Cloudflare のログに残ります。気になる場合は、curl でヘッダーとして渡してください（Windows では `curl.exe`）。

```sh
curl -H "Authorization: Bearer キー" "https://gakushoku-bot.<サブドメイン>.workers.dev/?test=preview"
```

| パラメータ | 内容                                                                    |
| ---------- | ----------------------------------------------------------------------- |
| `test`     | `lunch` / `dinner` / `preview`                                          |
| `date`     | `YYYY-MM-DD`。「今日」として扱う日付（省略時は今日）。`preview` はその翌日分 |
| `key`      | キー（ヘッダーで渡す場合は不要）                                        |
| `post`     | `1` のときだけ実際に Discord に投稿する。省略時は投稿内容を JSON で返すだけ |

### ローカル

```sh
cp .dev.vars.example .dev.vars   # テスト用チャンネルの Webhook を入れる
npm run dev
curl "http://localhost:8787/__scheduled?cron=0+1+*+*+*"   # 10:00 のジョブを実行
```

ローカル実行でも取得元には実際にアクセスします。何度も叩かないでください。

## 構成

```
src/
  index.js    エントリポイント（cron と動作確認エンドポイント）
  jobs.js     ジョブごとの処理と投稿内容の組み立て
  scraper.js  ページの取得とメニュー表の読み取り
  discord.js  Discord への投稿とテキストの無害化
  date.js     日本時間の日付計算
test/         テスト（架空のメニュー表を使う）
```

メニュー表は時期によって行の数が変わります（長期休み中は「夕食セット」の行がなくなる、学期中は「単品」「麺類」などが増えるなど）。そのため、行は位置ではなく見出しの名前で探します。日付は週見出しの「月」と各列の「日・曜日」から年月日を復元して照合します。こうすることで、休み中に更新が止まったページの同じ日付を拾いません。

## 停止方法

- **定期実行だけ止める:** `wrangler.jsonc` の `crons` を `[]` にして `npm run deploy` します。Cloudflare ダッシュボードの Worker の設定から Cron トリガーを削除しても止まります。
- **Worker ごと削除する:** `npx wrangler delete`
